### Evaluation method

Use **human-reviewed labels only** as ground truth. Do not use the model's own predictions, weak/evidence labels, or XGBoost confidence as ground truth.

Recommended protocol:

1. Export candidate events with `python scripts/export_xgboost_training_candidates.py`.
2. A human reviewer assigns the correct source class in `data/ml_labels.csv`.
3. Keep the reviewed labels independent from the model prediction.
4. Train the model using the project's normal pipeline.
5. Evaluate the saved model with `python scripts/evaluate_xgboost_reviewed.py`.
6. Report accuracy, balanced accuracy, precision, recall and macro F1.
7. Show the confusion matrix when asked for evidence.

## Judge explanation — short version

> “ThermoIntel uses XGBoost as a multiclass source classifier. We do not call model confidence accuracy. Accuracy is measured separately against human-reviewed thermal events that were not used as training ground truth. We report accuracy together with balanced accuracy, precision, recall, macro F1 and the confusion matrix so performance is visible across all event classes.”

## Important limitation

If `data/ml_labels.csv` contains no human-reviewed labels, there is **no defensible ground-truth accuracy number yet**. The system may calculate a holdout score against its weak evidence labels for development diagnostics, but that must be described as **weak-label validation**, not real-world accuracy.
